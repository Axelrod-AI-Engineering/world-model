Implementation: the ML stack, component by component

Technical briefing · Axelrod World Model · October 2026 · how each part would be built. Deployment is out of scope.

Summary. The world model works like version control over a causal graph. Learning of working memory and learning of long-term memory write to it, and only through commits. Each event's learning first runs on a staged copy; a person reviews everything the copy would commit, selects what to keep, and only that is committed. Inference reads committed versions on a branch that is never merged, so inference never learns.

Every component sits behind one interface with a contract: its inputs, outputs, the memories it reads and writes, and when it runs (engine/contracts.py; axelrod contracts). This page says, for each component, what the prototype does and what a production ML stack would use instead; the last section lists every contract. How it works shows where each one runs.

3. Review

ComponentPrototypeProduction stack
Staged reviewThe event's whole learning (working and long-term memory, and the day's distillation) runs on a copy of the state with a throwaway ledger; the difference is the review: items, moves, the ripple by order, what is learned (control/stage.py)A copy-on-write branch of the state store, so staging costs only what the event touches; deselecting items re-runs it on the branch
review_policyRules: new or deleted structure, text translation, large reweighting, low confidence (the tutorial reviews everything)The same rules, plus a calibrated score, learned from past decisions, that ranks the queue. Each reviewer decision, selection, and note becomes a training label.

10. Libraries

The prototype uses Python 3.12, Pydantic (the contracts), NumPy and SciPy. The production stack adds JAX and NumPyro, NetworkX, the Teachable AI Lab's Cobweb code, tigramite (PCMCI), rapidfuzz, a language model with schema-constrained decoding, and Parquet with DuckDB. The Literature tab gives the reasons and the references.

11. Simpler choices that won

ConsideredChosenWhy
Whitening embeddingsAn acuity cutoff per treeThe same effect without a preprocessing step.
One Cobweb tree for all dataA tree per data structure, plus trees over compositionsEach structure is categorized on its own terms, and a composite sees its parts as concepts.
Text embeddings for everythingStructured blocks; text only where the input is textMost objects are not text. How things move and respond is what makes them alike for forecasting.
One large VAR over every valueA sparse causal graph that borrows the VAR toolkitLarge Bayesian VARs handle many series, but they are re-estimated whole. The graph grows one reviewed interaction at a time.
An end-to-end neural forecasterNeural networks only produce vectorsKinds, dynamics, and forecasts stay explicit and inspectable.
Interactions proposed by a language modelInteractions from data and reviewPlausible text is not evidence.
